# Spring4D — IoC/DI em Delphi

## As 3 fases obrigatórias

```delphi
// 1. REGISTER — no Bootstrap, antes de qualquer resolve
GlobalContainer.RegisterType<TClienteService>.Implements<IClienteService>;
GlobalContainer.RegisterType<TClienteFDRepository>.Implements<IClienteRepository>;

// 2. BUILD — uma única vez, após todos os registros
GlobalContainer.Build;

// 3. RESOLVE — onde a dependência é necessária (formulário, factory)
LService := GlobalContainer.Resolve<IClienteService>;
```

## Lifetimes

| Lifetime | Quando usar |
|----------|------------|
| `SingletonPerContainer` (padrão) | Service, Repository — uma instância por container |
| `Transient` | Objetos com estado por operação |
| `SingletonPerThread` | Em ambientes multi-thread |

## Constructor injection (preferido)

```delphi
// NO AGENT: o construtor recebe a interface, Spring resolve automaticamente
constructor TClienteService.Create(ARepository: IClienteRepository);
begin
  FRepository := ARepository;
end;
```

## `[Inject]` (último recurso)

```delphi
// Usar só quando constructor injection não for possível (forms legados)
[Inject]
FRepository: IClienteRepository;
```

## Lazy<T> — dependências caras

```delphi
// A instância só é criada quando .Value é acessado pela primeira vez
constructor TRelatorioService.Create(AGerador: Lazy<IRelatorioGerador>);
begin
  FGerador := AGerador;
end;

procedure TRelatorioService.Gerar;
begin
  FGerador.Value.Gerar; // instanciado aqui
end;
```

## Anti-patterns

```delphi
// PROIBIDO — acoplamento ao container em runtime
GlobalContainer.Resolve<IClienteService>.Salvar(LCliente);

// CORRETO — resolver na composição root (form/factory), não no service
```

## Bootstrap.pas (padrão)

```delphi
unit Bootstrap;

interface
  procedure InicializarContainer;

implementation
  uses Spring.Container, ClienteService, ClienteRepository, ...;

  procedure InicializarContainer;
  begin
    GlobalContainer.RegisterType<TClienteService>.Implements<IClienteService>;
    GlobalContainer.RegisterType<TClienteFDRepository>.Implements<IClienteRepository>;
    // ... outros registros
    GlobalContainer.Build;
  end;
end.
```

Chamar `InicializarContainer` no `begin` do `.dpr`, antes de `Application.Run`.
```

```typescript
import * as vscode from 'vscode';
import * as fs from 'fs';
import * as path from 'path';
import * as os from 'os';

const LOCAL_KB = path.join(os.homedir(), '.claude', 'plugins', 'delphi-dev', 'knowledge', 'local');

export class RagWebviewProvider implements vscode.WebviewViewProvider {
  public static readonly viewType = 'delphi-dev.ragLearnings';

  resolveWebviewView(webviewView: vscode.WebviewView): void {
    webviewView.webview.options = { enableScripts: true };
    webviewView.webview.html = this.getHtml();
  }

  private getHtml(): string {
    const files = fs.existsSync(LOCAL_KB)
      ? fs.readdirSync(LOCAL_KB).filter((f) => f.endsWith('.md')).slice(-10).reverse()
      : [];

    const items = files.map((f) => {
      const date = f.slice(0, 10);
      const agent = f.replace(/^\d{4}-\d{2}-\d{2}-/, '').replace('.md', '');
      return `<li><strong>${date}</strong> — ${agent}</li>`;
    }).join('');

    return `<!DOCTYPE html>
<html>
<head>
  <meta charset="UTF-8">
  <style>
    body { font-family: var(--vscode-font-family); font-size: 12px; padding: 8px; }
    h2 { font-size: 13px; margin-bottom: 8px; }
    ul { padding-left: 16px; margin: 0; }
    li { margin-bottom: 4px; }
    .empty { color: var(--vscode-descriptionForeground); }
  </style>
</head>
<body>
  <h2>Recent Learnings (RAG)</h2>
  ${items.length > 0
    ? `<ul>${items}</ul>`
    : '<p class="empty">No learnings yet. Use delphi-dev in Claude Code sessions to capture knowledge.</p>'
  }
</body>
</html>`;
  }
}
```

## Padrão HelpInsight Delphi

```delphi
/// <summary>
/// Busca um cliente pelo identificador único.
/// </summary>
/// <param name="AId">Identificador único do cliente.</param>
/// <returns>Interface ICliente com os dados do cliente.</returns>
/// <exception cref="EClienteNaoEncontrado">Lançada quando o cliente não é encontrado.</exception>

## Regras

1. Documentar **apenas** interfaces públicas e métodos públicos — não métodos privados/protected
2. `<summary>` obrigatório — uma linha clara sobre o que faz
3. `<param>` para cada parâmetro — não repetir o nome, explicar o propósito
4. `<returns>` quando o método retorna algo não óbvio
5. `<exception>` para exceptions esperadas (as que o chamador deve tratar)
6. Não repetir o nome do método na descrição: "Busca cliente" não "BuscarCliente busca um cliente"
7. Em pt-BR por padrão, respeitar idioma do projeto

var

## Padrão LiveBindings FMX com FireDAC

Componentes necessários no DataModule:
- `TFDConnection` — conexão com banco
- `TFDQuery` — query de dados
- `TBindSourceDB` — ponte entre FireDAC e LiveBindings
- `TBindingsList` — gerenciador de bindings

## Binding de lista (TListView)

```
TBindSourceDB → TLinkListControlToField
  FieldName: campo do dataset
  Control: TListView
  ItemExpression: Item.Text (para TListView)
```

## Binding de campo individual (TEdit)

```
TBindSourceDB → TLinkControlToField
  FieldName: nome do campo
  Control: TEdit
  Track: True (atualiza em tempo real)
```

## TNavigator

Conectar ao mesmo `TBindSourceDB` para navegação automática (First/Prior/Next/Last/Insert/Delete/Post/Cancel).

## Armadilha comum

`TBindSourceDB` precisa estar no mesmo DataModule que o `TFDQuery`.
Usar `TBindSourceDB` de outro DataModule causa `EBindCompError` em runtime.
