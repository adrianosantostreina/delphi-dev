# msbuild vs dcc32 — Quando usar cada um

## dcc32 (compilador direto)
**Quando usar:** compilar uma única unit ou projeto simples, testes DUnitX, quando precisa de controle fino dos switches.

```batch
dcc32 -B -Q -E".\Win32\Debug" -N".\Win32\Debug\dcu" "Projeto.dpr"
```

| Switch | Significado |
|--------|------------|
| `-B` | Build all (recompila tudo) |
| `-Q` | Quiet (menos output) |
| `-E<dir>` | Diretório de saída do .exe |
| `-N<dir>` | Diretório dos .dcu |

## msbuild (via .dproj)
**Quando usar:** build completo do projeto com todas as configurações do .dproj, cross-compile mobile.

```batch
msbuild "Projeto.dproj" /p:Config=Debug /p:Platform=Win32 /v:minimal /clp:NoSummary
```

| Parâmetro | Valores comuns |
|-----------|---------------|
| `/p:Config` | Debug, Release |
| `/p:Platform` | Win32, Win64, Android, Android64, iOSDevice64 |
| `/v:minimal` | Output mínimo |

## Regra geral
- Projeto simples Windows: `dcc32`
- Cross-compile mobile: `msbuild`
- Integração CI: `msbuild` (mais previsível)
```

# Parsing de Erros do dcc32

## Formato da linha de erro

```
<arquivo>(<linha>) <severidade>: <código> <mensagem>
Unit1.pas(42) Error: E2003 Undeclared identifier: 'TStringList'
```

## Catálogo: identificador → unit faltante

| Identificador não encontrado | Unit a adicionar |
|-----------------------------|------------------|
| `TStringList`, `TStrings` | `System.Classes` |
| `TList<T>`, `TDictionary<K,V>`, `TObjectList<T>` | `System.Generics.Collections` |
| `Format`, `IntToStr`, `StrToInt`, `FloatToStr` | `System.SysUtils` |
| `TMemoryStream`, `TFileStream` | `System.Classes` |
| `TJSONObject`, `TJSONArray` | `System.JSON` |
| `TThread`, `TTask` | `System.Threading` |
| `TParallel` | `System.Threading` |
| `TPath`, `TDirectory`, `TFile` | `System.IOUtils` |
| `TEncoding` | `System.SysUtils` |
| `TRegEx` | `System.RegularExpressions` |
| `TForm` (VCL) | `Vcl.Forms` |
| `TForm` (FMX) | `FMX.Forms` |
| `TLabel`, `TButton`, `TEdit` (VCL) | `Vcl.StdCtrls` |
| `TLabel`, `TButton`, `TEdit` (FMX) | `FMX.StdCtrls` |
| `TFDQuery`, `TFDConnection` | `FireDAC.Comp.Client` |
| `TFDTable` | `FireDAC.Comp.Client` |
| `TRESTClient`, `TRESTRequest` | `REST.Client` |
| `TJSONPair` | `System.JSON` |

## Códigos de erro comuns

| Código | Significado | Ação |
|--------|------------|------|
| `E2003` | Undeclared identifier | Adicionar unit ao uses |
| `E2065` | Unsatisfied forward declaration | Implementar o método declarado |
| `F2613` | Unit not found | Verificar SearchPath no .dproj |
| `E2010` | Incompatible types | Revisar tipos dos parâmetros |
| `E1025` | Unsupported language feature | Feature requer versão mais nova do Delphi |
| `W1010` | Method ... hides ... | Adicionar `reintroduce` ou renomear |
```

# Parsing de Erros do msbuild

## Formato da linha de erro msbuild

```
<arquivo>(<linha>,<col>): error <código>: <mensagem> [<projeto.dproj>]
Unit1.pas(42,3): error E2003: Undeclared identifier: 'TStringList' [C:\Projeto\Projeto.dproj]
```

## Distinguir erro do compilador vs erro do msbuild

**Erro do dcc32 (via msbuild):**
```
Unit1.pas(42) Error: E2003 Undeclared identifier
```
→ Tratar como erro dcc32 — ver `parsing-erros-dcc.md`

**Erro do próprio msbuild:**
```
MSBUILD : error MSB1008: Only one project can be specified.
error MSB4057: The target "Build" does not exist in the project.
```
→ Problema no .dproj ou na invocação do msbuild

## Avisos do msbuild para ignorar

```
MSB3245: Could not resolve this reference
```
Geralmente inofensivo se o build completou com sucesso.

## Verificar se o build teve sucesso

Procurar no `build_log.txt`:
- Sucesso: `Build succeeded.` ou `0 Error(s)`
- Falha: `Build FAILED.` ou `N Error(s)` onde N > 0
```

## Protocolo de Build

### Passo 1 — Detectar Studio instalado

Verificar `C:\Program Files (x86)\Embarcadero\Studio\*\bin\rsvars.bat`:

```powershell
Get-ChildItem "C:\Program Files (x86)\Embarcadero\Studio\*\bin\rsvars.bat" |
  Select-Object FullName | Sort-Object FullName -Descending
```

- Nenhum encontrado → **PARAR** com mensagem: "RAD Studio não encontrado. Instale o RAD Studio ou crie `.delphi-dev.json` com `\"studio\": \"23.0\"` apontando para sua instalação."
- Um encontrado → usar esse
- Múltiplos → verificar `.delphi-dev.json` na raiz do projeto; se ausente, perguntar ao usuário qual usar

### Passo 2 — Verificar/gerar `build.bat`

Verificar se existe `build.bat` na raiz do projeto. Se não existir, gerar com este template:

```batch
@echo off
setlocal

set LOG=%~dp0build_log.txt
echo Build started: %date% %time% > "%LOG%"

call "C:\Program Files (x86)\Embarcadero\Studio\{VERSAO}\bin\rsvars.bat"

msbuild "%~dp0{PROJETO}.dproj" ^
  /p:Config={CONFIG} ^
  /p:Platform={PLATFORM} ^
  /v:minimal /clp:NoSummary ^
  >> "%LOG%" 2>&1

if %ERRORLEVEL% == 0 (
  echo BUILD OK >> "%LOG%"
) else (
  echo BUILD FAILED >> "%LOG%"
)

exit /b %ERRORLEVEL%
```

Substituir `{VERSAO}`, `{PROJETO}`, `{CONFIG}`, `{PLATFORM}` pelos valores detectados/configurados.

### Passo 3 — Executar build

```
Bash: cmd.exe /c "<abs-path>\build.bat"
```

**Nunca** capturar stdout. O bat redireciona para `build_log.txt`.

### Passo 4 — Ler log

```
Read: build_log.txt
```

Verificar última linha: `BUILD OK` ou `BUILD FAILED`.

### Passo 5 — Parsear erros

Carregar `skills/delphi-build/references/parsing-erros-dcc.md` para o catálogo de erros.

Para cada linha de erro no formato `<arquivo>(<linha>) Error: <codigo> <mensagem>`:
1. Extrair arquivo, linha, código, mensagem
2. Consultar catálogo: `E2003` → qual unit adicionar?
3. Montar lista de fixes

### Passo 6 — Aplicar fixes (se `--auto-fix` ativo)

Para cada unit faltante identificada:
1. Abrir o arquivo `.pas` com `Read`
2. Localizar a cláusula `uses` correta (interface ou implementation)
3. Adicionar a unit usando `Edit`
4. Seguir a regra `knowledge/core/uses-uma-unit-por-linha.md`

### Passo 7 — Loop de recompilação

Com `--auto-fix`: após aplicar fixes, recompilar (voltar ao Passo 3).
Máximo: 3 iterações. Se após 3 ainda houver erros, apresentar diagnóstico ao usuário.

### Passo 8 — Resultado final

**pt-BR:**
- Sucesso: "✅ BUILD OK — {N} unidades compiladas, 0 erros"
- Falha: "❌ BUILD FAILED — {N} erro(s) encontrado(s): [lista de erros com arquivo/linha]"

**en-US:**
- Success: "✅ BUILD OK — {N} units compiled, 0 errors"
- Failure: "❌ BUILD FAILED — {N} error(s): [list with file/line]"

## Flags suportadas

| Flag | Comportamento |
|------|--------------|
| `--release` | Config=Release |
| `--plat=Android64` | Platform=Android64 |
| `--auto-fix` | Aplica fixes automáticos de units faltantes, recompila |
| `--tests` | Compila e executa DUnitX (usa `dcc32 -B -Q -E -N` + `.exe --exit`) |

Se existir na raiz do projeto:

  "studio": "23.0",
  "default_config": "Debug",
  "default_platform": "Win32",
  "build_log": "build_log.txt",
  "auto_fix": false
}
```
Usar esses valores como padrão para o build.

## Sintaxe

```

/build --plat=Android64   → cross-compile Android
/build --auto-fix         → compila + corrige erros de unit automaticamente

Invoca o agent `delphi-builder` passando as flags fornecidas.

```
/build → delphi-builder (sem flags = Debug/Win32)
/build --auto-fix → delphi-builder com auto-fix ativo (máx 3 iterações)
/build --tests → delphi-builder compila + roda exe DUnitX --exit
```

# `.delphi-dev.json` — Configuração do Projeto

Arquivo opcional na raiz do projeto Delphi para personalizar o comportamento do plugin.

## Campos

| Campo | Tipo | Padrão | Descrição |
|-------|------|--------|-----------|
| `studio` | string | auto-detect | Versão do RAD Studio: `"22.0"`, `"23.0"`, `"37.0"` |
| `default_config` | string | `"Debug"` | Configuração padrão de build: `"Debug"` ou `"Release"` |
| `default_platform` | string | `"Win32"` | Plataforma padrão: `"Win32"`, `"Win64"`, `"Android"`, `"Android64"`, `"iOSDevice64"` |
| `build_log` | string | `"build_log.txt"` | Nome do arquivo de log do build |
| `auto_fix` | boolean | `false` | Se `true`, delphi-builder aplica fixes automáticos sem perguntar |
| `encoding_mode` | string | `"utf8-bom"` | Modo de encoding: `"utf8-bom"` (padrão) ou `"ansi"` (projetos pré-XE2) |
| `legacy_mode` | boolean | `false` | Se `true`, ativa o skill `delphi-legacy` automaticamente |

## Exemplo completo

```json
{
  "studio": "23.0",
  "default_config": "Debug",
  "default_platform": "Win32",
  "build_log": "build_log.txt",
  "auto_fix": false,
  "encoding_mode": "utf8-bom",
  "legacy_mode": false
}
```

## Gerado automaticamente

O comando `/build` cria `.delphi-dev.json` com os valores detectados se o arquivo não existir.
O arquivo deve ser commitado no repositório do projeto.
